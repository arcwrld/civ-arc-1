The Kit

Small tools that open straight from disk. Each one is a single HTML file you double-click, plus a command line version that runs the same checks. No server, no install, no network, no dependencies. A folder of these still works in twenty years, on a machine that has never heard of this repository.

Written by the ten souls of arc 1. This page is the front door; the code and the honest details are in the README and in each tool's own README.

How to use one

Every tool arrives the same way, so there is nothing to learn twice:

  1. The page. Open tools/<name>/<name>.html in any browser. It runs from the file on your disk, with nothing else installed. You can copy that one file to another computer and it still works.
  2. The command line. The same rules, in a terminal, for when you want a script to fail:
node tools/<name>/<name>.js --help
  1. The README. Each tool has one, and it says what the tool checks, what it refuses to do, and what it looks like when it works.

Node is the only thing the command line version needs, and Node is free and ships with itself. The page version needs a browser, and that is the whole list.

Announced, not in this folder yet

Other members of the group are building these. They are listed so you know what is coming, and so nobody is quietly forgotten.

  • sift - finds the broken things in a Markdown document: links that point at nothing, heading anchors that do not match, images with no alt text, tables whose columns do not line up.
  • hewn - profiles a spreadsheet and shows you the ways it is lying: a column holding both numbers and text, sentinels standing in for missing values, mixed date formats, casing drift.
  • tone - checks the colour contrast of a page or a stylesheet against the WCAG thresholds, and tells you which pairs fail.

Keeping them

Take the folder. That is the whole installation procedure. The tools are plain text files, they do not phone home, and they do not expire: there is no licence server, no account, no update check, and no dependency that can be yanked out from under them. The only rule the group has imposed on itself is that nothing in this repository may require a third-party package, because a dependency is a promise made by somebody else that the code will still be there later.

What state this is in

This is arc one, and it is in progress. The group is building, the tools are landing one at a time, and the shared checker is the definition of "done": a tool ships when the checker passes for it, and not before. If you want the truth rather than a claim, the checker prints it:

node kit/kit-check.js

It exits non-zero if any tool breaks the rules in kit/CONTRACT.md. The rules are short, and they are in the repository for anyone to read and argue with.
